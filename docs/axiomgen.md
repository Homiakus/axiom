# axiomgen — кодогенератор для Axiom

axiomgen генерирует типизированную Go-обвязку из `.axm` DSL-файла. Вместо
строковых регистраций activity с `map[string]any` вы получаете строго
типизированные структуры Input/Output, интерфейс `Activities` и адаптеры,
которые преобразуют типизированные вызовы в `axiom.Activity`.

## Быстрый старт

```bash
# Интерактивный TUI (выбор файла, настройка out dir и package)
go run ./tools/axiomgen

# Неинтерактивный режим
go run ./tools/axiomgen --file examples/axiom-files/welcome.axm

# С явным указанием выходной директории и имени пакета
go run ./tools/axiomgen --file welcome.axm --out ./generated --package flows
```

После генерации:

```go
import "myproject/generated"

// Создание engine без строковых регистраций:
engine, err := generated.NewWelcome(generated.WelcomeActivityImpl{})
```

## CLI-флаги

| Флаг | Значение по умолчанию | Описание |
|------|----------------------|---------|
| `--file` | (обязательный) | Путь к `.axm` файлу |
| `--out` | директория `.axm` | Директория для выходных файлов |
| `--package` | имя директории | Имя Go-пакета (автоматически sanitize) |

## Выходные файлы

axiomgen создаёт ровно два файла:

### `<domain>_axiom.gen.go` — всегда перегенерируется

Содержит:

- **Заголовок:** `// Code generated by axiomgen from <path>; DO NOT EDIT.`
- **Embedded исходник:** константа `<Domain>AXMSource` с полным текстом `.axm`
- **Хеш:** константа `<Domain>AXMHash` для проверки изменений
- **Константы activity:** `ActivitySendWelcomeEmail = "SendWelcomeEmail"`
- **Типизированные структуры:**
  ```go
  type SendWelcomeEmailInput struct {
      UserId *string `json:"userId"`
      Email  *string `json:"email"`
  }
  type SendWelcomeEmailOutput struct {
      Sent bool `json:"sent"`
  }
  ```
- **Интерфейс:**
  ```go
  type WelcomeActivities interface {
      SendWelcomeEmail(ctx context.Context, input SendWelcomeEmailInput) (SendWelcomeEmailOutput, error)
  }
  ```
- **Load/New функции:**
  ```go
  func LoadWelcome() (*axiom.App, error)
  func NewWelcome(impl WelcomeActivities, opts ...axiom.Option) (*axiom.Engine, error)
  ```
- **Адаптеры:** `adaptSendWelcomeEmail`, `decodeSendWelcomeEmailInput`, `encodeSendWelcomeEmailOutput`
- **Хелперы преобразования типов:** `axiomToInt`, `axiomToFloat`, `axiomToStringSlice`, и т.д.

Начинающийся с `DO NOT EDIT` заголовок сигнализирует: этот файл не редактировать
вручную. При следующем запуске axiomgen он будет полностью перезаписан.

### `<domain>_activities.go` — создаётся один раз

Содержит пустую реализацию-заглушку:

```go
package generated

import (
    "context"
    "fmt"
)

type WelcomeActivityImpl struct{}

func (WelcomeActivityImpl) SendWelcomeEmail(
    ctx context.Context, input SendWelcomeEmailInput,
) (SendWelcomeEmailOutput, error) {
    return SendWelcomeEmailOutput{}, fmt.Errorf("SendWelcomeEmail is not implemented")
}
```

Пользователь заменяет `fmt.Errorf(...)` на реальную реализацию. Файл помечен как
`Once: true` — при повторном запуске axiomgen он **не перезаписывается**.

## Умный merge при изменении .axm

Если `.axm` изменился и вы снова запускаете axiomgen:

### Новые activity → дописываются

axiomgen парсит Go AST существующего `*_activities.go`, находит уже реализованные
методы, и дописывает только новые заглушки в конец файла:

```go
// Было:
func (impl) SendUartRequest(...) { /* твой код */ }

// После перегенерации (добавили NewActivity в .axm):
func (impl) SendUartRequest(...) { /* твой код — нетронут */ }

func (impl) NewActivity(ctx context.Context, input NewActivityInput) (NewActivityOutput, error) {
    return NewActivityOutput{}, fmt.Errorf("NewActivity is not implemented")
}
```

### Изменённые поля → compile error

Если у существующей activity изменился тип или имя поля, `*_axiom.gen.go`
обновляет Input/Output-структуры. Go-компилятор сразу покажет ошибку
несоответствия типов в вашем `*_activities.go`. Это compile-time safety —
вы не пропустите изменение.

### Удалённые activity → compile error

Метод остаётся в `*_activities.go`, но интерфейс в `.gen.go` его уже не содержит.
Go-компилятор сообщит, что `XxxActivityImpl` не реализует интерфейс. Нужно
вручную удалить устаревший метод или оставить для справки (закомментировав).

### Защита от случайной перезаписи

Если `*_activities.go` был полностью переписан вручную и не содержит ни одного
метода-получателя (например, вы удалили все заглушки и написали свою структуру),
smart merge **не срабатывает** — файл остаётся нетронутым.

## Diff-отчёт

При каждом запуске axiomgen сравнивает текущий `.axm` с предыдущей версией
(извлечённой из embedded-константы в `.gen.go`). Diff показывает:

- **Добавленные activity** (`+`): название, все input/output поля с типами
- **Удалённые activity** (`-`): название, предупреждение что метод останется в `_activities.go`
- **Изменённые activity** (`~`): для каждого поля — добавлено (`+`), удалено (`-`), изменён тип (`~`)

Если `.gen.go` не существует (первая генерация), diff не показывается.

## Типы полей: маппинг .axm → Go

axiomgen выводит типы полей из `.axm` и конвертирует в Go-типы:

| .axm type | Go type | Nullable (.axm `?`) |
|-----------|---------|---------------------|
| `String` | `string` | `*string` |
| `Int` | `int` | `*int` |
| `Float` | `float64` | `*float64` |
| `Bool` | `bool` | `*bool` |
| `Time` | `string` | `*string` |
| `Duration` | `string` | `*string` |
| `Object` | `map[string]any` | `*map[string]any` |
| `Any` | `any` | `*any` (pointer to any) |
| `List<T>` | `[]T` | `*[]T` |
| `Map<K,V>` | `map[string]any` | `*map[string]any` |

Типы для `input`-полей выводятся из контекста (связывание с context, signal,
computed, fact), а не берутся напрямую из `.axm` — это позволяет axiomgen
генерировать наиболее точный тип.

## Передача комментариев

Комментарии из `.axm` (строки с `#`) переносятся в сгенерированный Go-код:

```
.axm:                                .gen.go:
# sends welcome message              // sends welcome message
activity SendWelcomeEmail:           ActivitySendWelcomeEmail = "SendWelcomeEmail"

  input:                             // sends welcome message
    userId = RegisteredUser.id # uid type SendWelcomeEmailInput struct {
                                     // uid
                                     UserId *string `json:"userId"`
```

Комментарии привязываются к ближайшей следующей декларации или полю.

## Состав axiomgen

```
tools/axiomgen/
├── main.go                    # Точка входа: парсинг флагов, вызов Run
├── go.mod                     # Отдельный модуль (axiom/tools/axiomgen)
└── internal/
    ├── codegen/
    │   ├── codegen.go         # Generate() — основная логика генерации
    │   │                      # Diff() — сравнение двух Module
    │   └── codegen_test.go    # Тесты генерации
    ├── generate/
    │   ├── generate.go        # Preview(), Run() — оркестрация
    │   │                      # mergeActivityStubs() — умный merge
    │   │                      # extractAXMSource() — извлечение старого .axm
    │   └── generate_test.go   # Тесты Preview, Run, merge
    └── tui/
        └── model.go           # Bubble Tea TUI (4 шага)
```
