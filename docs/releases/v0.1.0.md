# Axiom v0.1.0

`v0.1.0` is the first versioned public baseline of Axiom. It freezes the current pre-v1 expectations strongly enough for downstream consumers to depend on a tag instead of an unversioned pseudo-version, while keeping room for intentional API refinement before `v1.0.0`.

## Recommended starting point

For new Go applications, start with the declarative `model` frontend and the runtime path:

```text
Definition -> Plan -> Engine -> Run
```

Use `axiom.Flow` for compact reducer-style logic, AXM for externally stored models/tooling, and TOML for decision tables.

## Highlights

- typed model helpers and `ActTyped` fail-fast boundaries;
- structured `AX509`/`AX510` builder diagnostics instead of panic or swallowed literal errors;
- enforced activity retry, timeout and process-local `once` concurrency semantics;
- full arithmetic support across AXM parser, fallback evaluator and fast VM;
- exact signed 64-bit `Int` semantics with overflow detection;
- stable runtime execution metadata through `runtime.*` queries;
- parser crash hardening discovered by fuzz testing;
- CI gates for tests, race detector, vet, vulnerability scan, fuzz smoke tests, external consumer, examples and benchmarks.

## Runtime policy semantics

`retry: N` currently performs at most `N + 1` handler calls inside one process and one leased task. `timeout` applies to each handler attempt. `concurrency: once` serializes calls of one activity inside one `Engine`; `parallel` adds no serialization.

`latest` and `first` remain production-blocked with `AX508` because safe behavior requires atomic task supersession. Durable retry with backoff/`NextAttemptAt` remains a later reliability layer.

## Compatibility

Axiom remains pre-v1. Minor releases may intentionally evolve public API, but breaking changes must be documented and should include a migration path whenever practical. See [`../versioning.md`](../versioning.md).

## Upgrade / install

After the release tag exists:

```bash
go get github.com/Homiakus/axiom@v0.1.0
```

## Known limitations

- no distributed execution/activity locking across Engine instances;
- no durable handler retry/backoff queue yet;
- no production-safe `latest/first` task supersession yet;
- policy `catch:` dispatch is not implemented in the verified runtime path;
- timer triggers do not yet provide a complete wall-clock scheduler contract;
- AXM imports have syntax/AST support but no public resolver/linker;
- Typed Go Flow effects occur before `FlowStore.Save`;
- automatic transition to execution `Completed` is not yet a public guarantee.

See [`../../CHANGELOG.md`](../../CHANGELOG.md) and [`../runtime-semantics.md`](../runtime-semantics.md) for the complete baseline.
