# Security policy

## Reporting a vulnerability

Do not publish exploit details, secrets, or sensitive reproduction data in a public issue.

Use GitHub's private **Report a vulnerability** flow for this repository when it is available. If the private reporting flow is unavailable, open a public issue containing only a request for a private contact channel; do not include technical exploit details in that issue.

A useful private report includes:

- affected commit, tag, or package;
- impact and realistic attack scenario;
- minimal reproduction steps;
- whether credentials, user data, files, or external systems are exposed;
- suggested mitigation, when known.

## Supported versions

Until a release support policy is published, only the current `main` branch is considered for security fixes. This statement does not guarantee that every commit on `main` is production-ready.

## Sensitive data

Never commit API keys, access tokens, passwords, private certificates, production database paths, or personal data to examples, tests, issues, or pull requests.
